# XHS_260731175346 云端信息（消息/媒体）调用逻辑

> 版本：XHS_260731175346.apk（moduleVersionCode 23，2026-07-31 17:53:46）
> 说明：XHS 是一个小红书（com.xingin.xhs）增强型 LSPosed 模块，**不连接作者自建云端服务器**。它的"云端"是小红书自身的业务云端：模块通过 Hook 小红书客户端内部方法，从**长连接进程收到的服务端消息**与**主进程笔记详情响应**中获取/拦截云端数据，实现防撤回、去水印与媒体保存。本文梳理该调用链。

---

## 一、云端数据通道（模块获取信息的两个来源）

| 通道 | 进程 | 数据内容 | 模块动作 |
| --- | --- | --- | --- |
| IM 长连接 | `com.xingin.xhs:longlinkNew` | 小红书云端推送的服务端消息，含撤回指令 | Hook `getServerRevokeMsg` 等，阻断撤回 → 防撤回 |
| 笔记详情 HTTP | `com.xingin.xhs`（主进程） | 云端返回的 `note` 笔记对象（图片/视频/音频/保存配置） | Hook 响应解析，提取去水印媒体 URL → 解锁保存/下载 |

模块自身**不包含**业务 API 域名、鉴权头或云端 Token——所有连接参数、请求体均由小红书客户端在运行时提供（见 `XHS_260731175346-urls.tsv`，静态 URL 仅三方库文档）。

## 二、完整调用链

### 0. 入口总览

```
小红书 App 启动（主进程或长连接进程）
   │
   ▼
LSPosed 框架加载模块
   │
   ▼
ModuleMain.onPackageLoaded(pkg)              ← 进程名过滤
   │     仅 com.xingin.xhs / com.xingin.xhs:longlinkNew
   │
   ├── System.loadLibrary("native")          ← 加载 libnative.so
   ├── ModuleInit.e(["loadSo", dataDir])     ← native 初始化，注入 dataDir
   └── C1076.f3469.mo213()                   ← native Hook 安装主入口（核心逻辑在 native）
         │
         ▼
   libnative.so（native 层）
     ├── DexKitBridge 在目标 APK DEX 中查找方法
     │     getMessageDaoMethod / getMessageByIdMethod / getServerRevokeMsg
     ├── LibXposed HookBuilder.intercept() 安装 Hook
     ├── 长连接进程：拦截服务端撤回消息 → 防撤回
     └── 主进程：拦截笔记响应 → 提取去水印媒体 URL
```

### 1. 模块加载：`ModuleMain.onPackageLoaded`

文件：`com/xingin/xhss/ModuleMain.java`

1. 取 `ModuleLoadedParam.getProcessName()`。
2. 仅当进程为 `com.xingin.xhs`（主进程）或 `com.xingin.xhs:longlinkNew`（长连接进程）且为首个包时继续。
3. `System.loadLibrary("native")` 加载 `libnative.so`。
4. 调用 `ModuleInit.e(["loadSo", dataDir])`（`ModuleInit.e` 为 native 方法），把目标应用 dataDir 交给 native。
5. 记录框架信息日志：`frameworkName / frameworkVersion / moduleVersionCode = 23 260731175346 2026-07-31 17:53:46`。
6. 调用 `C1076.f3469.mo213()` —— **native Hook 安装主入口**，随后记录 `load <pkg> cost <ms>`。

> 说明：`C1076.mo213()` 是 native 方法。Java 层看不到 hook 的具体安装逻辑，全部下沉到 `libnative.so`。

### 2. native Hook 安装（libnative.so）

`C1076` 是单例 hook 单元，静态定义三个目标方法名（`C1076.f3467`）：

```java
String[] f3467 = {
    "getMessageDaoMethod",   // 消息 DAO 访问方法
    "getMessageByIdMethod",  // 按消息 ID 查询方法
    "getServerRevokeMsg",    // 服务端撤回消息处理方法
};
```

native 层职责：

- 用 `DexKitBridge`（org.luckypray.dexkit）在目标 APK 的 DEX 中按方法名/特征定位真实方法。
- 用 `io.github.libxposed` 的 `HookBuilder.intercept()` 安装拦截。
- Hook 成功与否、异常均通过 `AbstractC1008` 基类上报（`C1085.m1764` 记录 `"run <class> hook error"` 等日志）。

### 3. 长连接进程初始化与防撤回（C0011 分支）

文件：`xhss/C0011.java`（case 12，`L81f`）

1. 取 `Application`，`System.loadLibrary("mmkv")`。
2. `MMKV.initialize(application, dataDir + "/config")` —— MMKV 存到目标应用 `/config` 目录。
3. 读 `ModuleLoadedParam.getProcessName()`：
   - 非 `com.xingin.xhs:longlinkNew` → 跳过本分支。
4. 长连接进程内：
   - 计算 `sourceDir` 哈希 + `versionCode`，与 MMKV 中缓存 `hash`、`moduleVersionCode` 比对；不一致则重建 `DexKitBridge`。
   - 校验 `getMessageDaoMethod` / `getMessageByIdMethod` / `getServerRevokeMsg` 三个方法名是否已缓存到 MMKV；缺失则重新查找。
   - 调用 `C1144.f3704.m1844(false)`（native，返回撤回处理 `Method`）初始化防撤回。
   - 日志 `防撤回已加载到长连接进程`。
5. 关闭并释放 `DexKitBridge`（`C1085.f3503`）。

> 长连接进程是小红书 IM 与云端的常驻通道。模块在这里安装防撤回 Hook，即可在云端下发撤回指令时阻止其生效。

### 4. 主进程笔记媒体提取（C0911 桥）

`m1471(LinearLayout, Dialog, note)` 构造笔记操作弹窗，从云端返回的 `note` 对象提取：

| --- | --- | --- |
| `note.mediaSaveConfig` | `disableSaveMedia` / `disableWaterMark` | 写入 `false`，解锁保存 / 去水印 |
| `note.soundInfo` | `url` | 音频下载 |

## 五、Native 保护要点

1. **Hook 主体在 native**：`C1076.mo213()`、`C1144.mo213()` 均为 native 方法，具体 Hook 目标与安装逻辑不在 Java 层明文。
2. **方法名混淆**：Java 层只暴露 `getMessageDaoMethod` / `getMessageByIdMethod` / `getServerRevokeMsg` 三个目标名，其余 hook 目标由 `libnative.so` 运行时用 DexKit 查找。
3. **字符串下沉 native**：native 有独立字符串池解码（`C0911.m1473(long)`、`m1478(long)`），与 Java 层 `m1313(long)` 机制对应，业务字符串大量藏于 native。
4. **业务加密**：`AbstractC0561.m1007` 为 PBKDF2WithHmacSHA256 + GZIP + AES/CBC/PKCS5Padding + 密文与派生密钥异或 + 字节反转 + 无填充 Base64。
5. **无自建服务器**：模块不保存云端域名/Token，一切连接数据依赖被 hook 的小红书客户端运行时提供。
