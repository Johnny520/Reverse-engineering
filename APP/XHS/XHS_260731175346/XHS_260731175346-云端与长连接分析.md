# XHS_260731175346 云端与长连接分析

## 结论

该 APK 的核心不是独立连接自建云端服务器，而是一个 LSPosed/Xposed 模块。它只在以下目标进程加载：

- `com.xingin.xhs`
- `com.xingin.xhs:longlinkNew`

第二个进程名明确表明它会进入小红书客户端的长连接消息进程。模块通过 Hook 和 DexKit 在目标应用的 DEX 中查找消息相关方法，因此小红书业务服务器的地址、鉴权头、请求体与长连接实际连接参数由目标应用在运行时提供，不在此模块 APK 内以静态明文保存。

## 网络组件与权限

- Manifest 声明了 `android.permission.INTERNET`。
- 打包包含 OkHttp `5.4.0` 的通用实现，包含 HTTP/1.1、HTTP/2、TLS、代理与 WebSocket 支持。
- `C1027.java` 使用 OkHttp 处理下载；其 URL 参数由调用方传入。
- `libnative.so` 的可见 URL 只有构建工具链字符串 `https://android.googlesource.com/toolchain/llvm-project`，不是业务服务器。

## 业务服务器地址扫描结果

已检查以下位置：

- 已还原的 Java 字符串池明文。
- `resources/`、`assets/` 与 Manifest。
- `libnative.so` 中可打印 ASCII 字符串。
- OkHttp、`java.net.URL`、WebSocket、Retrofit/HTTP 调用引用。

结果：没有发现该模块自身硬编码的业务 API 主机、IP、WebSocket 地址、授权服务器或云端 Token。`XHS_260731175346-urls.tsv` 中的地址均为 DialogX、Gson、SLF4J、JetBrains 等三方库文档链接。

## 与小红书云端的边界

模块 Hook 的对象是已经运行的小红书客户端；因此它能接触到小红书长连接收到的服务端消息，例如 `getServerRevokeMsg` 对应的撤回消息处理路径。静态分析只能证明模块介入该处理链，不能从模块 APK 单独推出小红书运行时连接的完整服务器域名列表。
