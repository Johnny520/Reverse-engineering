`fallback/sources/` 是 JADX `--decompilation-mode fallback` 对全部 477 个类的指令级 Java 输出。它优先保留跳转、异常边和寄存器数据，可读性低于 `restored-sources`，但对普通 JADX 失败的 `p000/k8.java:afterHookedMethod` 给出了完整指令体，没有 `Method not decompiled` 抛错占位。

## 11. 恢复精度与核验

- `restored-sources` 内 `C0341oa` 和 `.m915(` 全目录检索结果为 0。
- `纯明文源码/sources/p001` 内 `C0134a`、`m799`、`m1098`、`m1099`、`m1101`、`m1102`、配置密钥和 `javax.crypto` 检索结果均为 0。
- `纯明文源码/plaintext-config` 共 8 个 JSON，内容与独立 `decrypted-config` 目录逐文件 SHA-256 一致。
- 2,012 个直接常量数组调用已替换；3 个 JADX 拆分数组调用和 4 个指令转储字符串也已手动核对。
- 8 份远程明文配置都通过 PowerShell `ConvertFrom-Json` 解析验证。
- 普通 JADX 的唯一方法级结构化缺口 `C0283k8.b.afterHookedMethod` 已依据 `k8$b.smali` 恢复成有效 Java；缺失的 `l8` 清理任务也已依据 `l8.smali` 恢复为 `RunnableC0297l8.java`。fallback Java 与 Smali 继续作为逐指令证据。
- `纯明文源码` 内 `Method not decompiled` 占位检索结果为 0。
- 部分 Java 仍呈现大量 `while + hashCode + switch` 结构，这是 APK 字节码内原有的控制流平坦化痕迹，不是未恢复的字符串密文。
- Java 是从 DEX 重建的可读源码，而非开发者原始 Gradle/Kotlin 工程；变量名、注释、源文件分组和原始 Kotlin 语法在 DEX 构建阶段已经丢失。
- 本次交付是静态恢复与内容验证，未执行目标 APK，也未将反编译 Java 重建为新 APK。
