# 获取用户云端数据工具 — 使用说明

## 1. 工具是什么

`get_user_cloud_data.py` 用 Python 复现「挖红薯呀」Android 客户端（`p000/n90.java`）的**授权验证请求**，向作者服务器 `verify.php` 发送 POST 验签，获取**指定授权码 + 小红书 ID** 对应的云端授权数据。

**它做什么：**

- 按授权码前缀自动选择接口与 HMAC 密钥（`WHS-X-` → 正式接口，`WHS-Y-` → 公开接口）
- 离线构造请求签名 `sign = URLEncode(Hex(HmacSHA256("key=…&redbook_id=…", 密钥)))`
- 发送请求、解析 JSON 响应
- 复现客户端**二次验签**逻辑，校验服务器响应签名是否有效
- 输出授权状态与云端原始数据

**它不能做什么：**

- 不能凭空生成有效激活码——激活码有效性由**服务器**判定（`code==200`）
- 不能绕过服务器验证——工具只是模拟客户端正常行为，服务器仍是最终判官
- 只能查询**你自己持有的**激活码；用它批量探测他人激活码属于滥用

**环境要求：** Python 3.8+，仅标准库，Windows / Linux / macOS 均可直接运行，无需安装任何第三方依赖。

---

## 2. 快速开始

```bash
# 进入工具所在目录
cd "挖红薯呀"

# 离线自检（验证本机环境与签名逻辑，不联网）
python get_user_cloud_data.py --selftest

# 查询某授权码 + 用户ID 的云端授权数据
python get_user_cloud_data.py --key WHS-X-你的激活码 --uid 小红书用户ID

# JSON 格式输出（便于脚本/程序调用）
python get_user_cloud_data.py --key WHS-X-你的激活码 --uid 小红书用户ID --json
```

> `--uid` 就是客户端参数里的 `redbook_id`（小红书账号标识）。

---

## 3. 参数说明

| 参数 | 必填 | 默认 | 说明 |
|------|:---:|------|------|
| `--key` | 是* | — | 激活码，必须以 `WHS-X-` 或 `WHS-Y-` 开头，否则报错 |
| `--uid` | 是* | — | 小红书用户 ID / `redbook_id` |
| `--timeout` | 否 | 8 | 请求超时秒数（与客户端一致） |
| `--json` | 否 | 关 | 以 JSON 输出完整结果 |
| `--selftest` | 否 | — | 离线自检，不发网络请求（此时无需 `--key`/`--uid`） |

\* 仅在使用 `--selftest` 时可不填。

## 4. 输出示例与解读

### 4.1 友好文本输出

```
云端数据（授权验证）：
  接口      : https://anjao2024.top/auth/verify.php
  授权码前缀: WHS-X-
  响应验签  : 通过
  服务器 code: 200
  服务器 msg : ok
  授权状态  : 已授权（code=200 且验签通过）
  云端原始数据:
{
  "sign": "a1b2…",
  "code": 200,
  "msg": "ok"
}
```

### 4.2 JSON 输出（`--json`）

```json
{
  "ok": true,
  "endpoint": "https://anjao2024.top/auth/verify.php",
  "secret_prefix": "WHS-X-",
  "authorized": true,
  "sign_valid": true,
  "server_code": 200,
  "server_msg": "ok",
  "cloud_data": { "sign": "…", "code": 200, "msg": "ok" }
}
```

字段含义：

| 字段 | 含义 |
|------|------|
| `ok` | 请求链路是否成功（网络/解析层面） |
| `endpoint` | 实际请求的接口 URL |
| `secret_prefix` | 授权码前缀（用于区分正式/公开接口） |
| `sign_valid` | 客户端二次验签结果：服务器响应签名是否通过本地 HMAC 校验 |
| `server_code` / `server_msg` | 服务器返回的业务 code 与 msg |
| `authorized` | **最终授权结论** = `sign_valid` 且 `server_code == 200` |
| `cloud_data` | 服务器返回的完整原始 JSON |
| `error` | `ok=false` 时的错误信息（`network_error` / `http_error` / `invalid_json` 等） |

### 4.3 退出码

| 退出码 | 含义 |
|:---:|------|
| 0 | 查询成功且授权通过 |
| 1 | 查询成功但未授权 / 激活码无效（可看 code 与 msg） |
| 2 | 网络错误 / HTTP 错误 / 响应非 JSON / 参数错误 |

脚本化的用法：

```bash
python get_user_cloud_data.py --key WHS-X-xxx --uid 12345 --json
# 判断 $? 是否为 0 即可知道激活码是否有效
```

## 6. 常见问题

**Q：提示「无效授权码格式」？**
激活码必须以 `WHS-X-` 或 `WHS-Y-` 开头。确认没有复制错。

**Q：`server_code` 不是 200？**
激活码无效、过期或已被服务器拉黑。这是服务器的判定结果，工具无法改变。可关注 `server_msg` 里的原因。

**Q：`sign_valid` 为 false？**
服务器响应签名校验失败，说明响应被代理篡改，或服务器协议已更新（此时 `--selftest` 仍应通过，因为本机签名逻辑正确）。

**Q：提示 `network_error`？**
服务器不可达、DNS 失败或超时。可用 `--timeout` 调大超时，或检查网络/代理环境。

**Q：Windows 下中文乱码？**
工具已统一 UTF-8 输出；若终端仍是乱码，可先执行 `chcp 65001` 切换代码页。
