## 4. 云端接口和调用逻辑

### 4.1 密钥验证接口

来源：`p000\n90.java`，方法 `m2675O()`、`m2649M()`。

- **方法**：`POST`
- **接口 A**：`https://anjao2024.top/auth_public/verify.php`
- **接口 B**：`https://anjao2024.top/auth/verify.php`
- **Content-Type**：`application/x-www-form-urlencoded`
- **超时**：连接和读取均为 8000 ms
- **请求字段**：

```text
key=<URL编码后的模块密钥>
redbook_id=<URL编码后的红书账号/标识>
sign=<HMAC-SHA256(request_without_sign, secret)>
```

`request_without_sign` 的实际顺序为：

```text
key=<key>&redbook_id=<redbook_id>
```

签名使用 UTF-8 字节和 `HmacSHA256`，输出小写十六进制。X 类密钥使用 `XkT+...`，Y 类密钥使用 `lQF7...`；接口根据密钥前缀 `WHS-X-` / `WHS-Y-` 选择。

**响应校验**：读取 JSON 的 `sign` 字段，删除 `sign` 后将剩余字段名按字典序排序，以 `&` 连接 `key=value`，再用同一 secret 计算 HMAC-SHA256。校验失败返回 `sign_verify_failed`，无签名返回 `sign_missing`，网络异常返回 `network_error`，密钥前缀不匹配返回 `invalid_key_format`。

当响应 `code == 200` 且签名通过时，模块将 `uid`、`ok=true`、`akey` 写入 `xp1_license` SharedPreferences。

### 4.2 版本检查接口

来源：`p000\wb1.java`，方法 `m4964t()`。

- **方法**：`GET`
- **接口**：`https://anjao2024.top/auth_notice/version_check.php`
- **查询参数**：`module_version=30121&app_version=<宿主版本号>`
- **超时**：连接和读取均为 5000 ms
- **成功条件**：JSON 顶层 `code == 200` 且存在 `data`
- **读取字段**：`need_update`、`min_module_version`、`min_app_version`、`update_info.title`、`update_info.content`、`update_title`、`update_content`

模块把版本阻断状态写入 `vck_prefs`：

```text
vc_block = true/false
vc_block_ts = 1_<当前毫秒时间戳>|<HMAC-SHA256(1_<时间戳>, anjao_vc_salt)>
```

本地校验 `vc_block_ts` 的签名后决定是否继续显示联网验证提示。版本接口异常、空响应、非 200 或数据缺失都会走联网验证提示流程。

## 7. 结论与限制

- APK 中确实包含云端依赖，至少有 3 个 `anjao2024.top` 接口。
- 云端鉴权不是简单明文比较，而是 HMAC-SHA256；请求和响应均有签名校验。
- 关键 URL、盐值、字段名和两套固定签名密钥已从 XOR 字符串中静态还原。
- 输出目录包含可阅读的 Java 反编译代码、资源和 Smali；它们可用于逐文件阅读和核对。
- JADX 有 11 个方法反编译失败/不完整，不能把所有 Java 文件当作原作者源码；这些位置应结合对应 Smali 阅读。
- 本报告列出的是静态发现的 URL 和调用证据，不代表本次分析访问过这些地址，也不代表每个 URL 在当前版本运行时都会被调用。
